EXECUTIVE RESULT

Version J was implemented as a new project without overwriting any supplied source. It preserves the exact constitutional default editor and the permanent native control plane, consolidates the original K facade and the generalized q runtime onto one policy/heap/epoch/event core, and adds the Android components that require native declarations or consent owners.

The source compiles for Android API 36 with and without kotlin-reflect. Release, debug, JVM unit tests, release vital lint, and debug lint all completed successfully. Five JVM tests passed; lint reported 0 errors and 15 warnings. The supplied installable is zip-aligned and signed with the standard Android debug certificate using APK Signature Scheme v3.

API 36 runtime validation was attempted, but could not be completed on this host. There is no /dev/kvm. A software-emulated x86_64 API 36 guest mounted Android's dynamic partitions and started system services, but system_server repeatedly missed watchdog deadlines and restarted before Package Manager could finish an APK install. Therefore no candidate behavior is labeled emulator-verified below. This is an infrastructure-blocked runtime gap, not evidence that the app passed or failed those scenarios.

Comparison/Arena source decisions:

- maintestredo1h.kt (“H”, Arena /4) contributed comparison ideas but contains an undefined controller `a`, unsafe bridge assumptions, and multiple WebView ownership. Those mechanisms were rejected.
- maintest1.kt and the related accessibility configs contributed the 128-stroke gesture concept and comparison coverage. Gesture primitives were retained in the structured accessibility portal, not copied as a parallel bridge.
- Arena /2's TSV entry route was retained as a thin facade over the same runtime.
- Arena /3's separate accessibility-overlay modes were retained only where a separate overlay renderer is actually justified. That renderer exposes only O, is tied to the creating epoch, and is not a second application runtime.
- Manifest/root/permission/stop helpers were salvaged as thin capability helpers. Broken controllers, multiple heaps, multiple policy engines, and per-feature reflection systems were rejected.

2. ARCHITECTURE AND DATA FLOW

Native shell
  -> owns the always-available gear, safe-inset placement, visibility modes, volume-key recovery, exact editor recovery, policy editors, authentication controls, Android settings/consent entry points, stop/revoke/recreate, and log export
  -> never requires DOM cooperation, K, or JavaScript to open

Primary WebView
  -> one process-persistent Core WebView held through MutableContextWrapper and reparented between Activity/runtime ownership
  -> exposes K and mirror aliases to the same Bridge object
  -> applies top-level, subresource, and service-worker WebView network policy
  -> converts page/document trust boundaries, including document.open/write/close hooks, into epoch revocation

Unified Bridge and PolicyEngine
  -> checks Bridge master state, Sandbox, document authentication, then Black/White/Gray policy in that order
  -> canonicalizes operation kind, declaring class, member, and resolved signature
  -> routes legacy Java facade, q/k grammar, TSV, Java reflection, and Kotlin reflection through the same audit and decision path

Heap / epoch / event core
  -> epoch-scoped handles with retain/release and reference-aware cleanup
  -> callbacks, interface proxies, live ports, and nested-async pins expire with the page epoch
  -> fixed worker pool of 4; heap limit 4096; normal queue 1024; urgent queue 256; dropped-event accounting
  -> main-thread dispatch (`!`), asynchronous calls, cleanup (`~`), and stable error prefixes share one executor path

Android portals
  -> RuntimeService, NotificationPortal, ProjectionService, AlarmPortal, BroadcastEvents, ContentEvents, FileEvents, and GlobalService own only the Android lifecycle/manifest/consent work that JavaScript cannot declare
  -> callbacks feed the same Core port/event/epoch machinery
  -> GlobalService snapshots and reacquires accessibility nodes instead of retaining recycled node/event objects

5. SURGICAL CHANGE SUMMARY

- Created a separate Version J candidate; no supplied file was overwritten, deleted, renamed, or labeled obsolete.
- Preserved the exact original editor and moved security/recovery controls exclusively into permanent native views.
- Added a native gear above the WebView with WindowInsets/display-cutout handling, original visibility modes, volume recovery, and long-press editor recovery.
- Separated Bridge OFF, Sandbox ON/OFF, document password authentication, and Cut HTML Internet into independent persisted/global or ephemeral/document states as appropriate.
- Bridge defaults OFF; Sandbox defaults ON. Turning Bridge OFF bumps the epoch and releases page-owned authority immediately even if JavaScript still sees the interface until reload.
- Replaced ambiguous list behavior with canonical scopes: all, package:, class:, member:, signature:. Matching is normalized and deterministic. Blacklist always wins; unmatched calls prompt.
- Migrated old numeric list keys without silently inverting them: legacy entries are represented explicitly as `legacy:` substring rules in their historically corresponding lists.
- Routed Java and Kotlin reflection through one PolicyEngine and DebugLog path.
- Consolidated original K methods (sz, cls, c, n, x, u, g, s, a, p, del) and generalized q/k/tsv/cap methods onto one Core heap/resolver rather than retaining parallel runtimes.
- Added deterministic overload/varargs scoring and coercion for primitives/boxed types, numbers, chars, enums, null, arrays, handles, and varargs.
- Added bounded queues, drop counts, fixed workers, port-ready/closed events, explicit retain/release, nested async pinning, proxy cleanup, and epoch ownership.
- Kept one primary runtime WebView. RuntimeService attaches to Core; it does not create a duplicate runtime.
- Added a separately justified accessibility overlay WebView only; it exposes O, not K, and closes with its epoch.
- Implemented WebView network cutting at navigation, subresource, and ServiceWorkerClient surfaces, with normalized IDN host matching and exact-host/subdomain rules that reject deceptive suffix matches.
- Added structured accessibility windows/nodes, state/action metadata, safe reacquisition, global actions, setText/focus/scroll, coordinate gestures, up to 128 gesture strokes, screenshots, events, and emergency overlay recovery.
- Added Android-declared notification, runtime, projection, alarm, broadcast, content, and file portals feeding the common event machinery.
- Added an app-owned vector icon after packaging inspection found that a framework drawable reference produced a dangling icon resource in the first package attempt.
- Added host tests for exact editor bytes and policy precedence/matching.

Compression decisions:

- One primary WebView, one heap, one resolver, one PolicyEngine, one epoch authority, and one event delivery system.
- Legacy APIs are adapters, not duplicate implementations.
- Android portals contain lifecycle/declaration/consent work and forward into Core.
- No networking dependency was added to simulate a false firewall.
- No AndroidX framework was added.
- No lexical minification or deliberately opaque identifiers were used.
- The only second WebView is the accessibility overlay renderer; it is capability-scoped and cannot host the main K runtime.

Rejected duplicated mechanisms:

- Test2-style independent service WebView/runtime.
- Arena controller/bridge copies and separate policy semantics.
- Retained AccessibilityEvent/AccessibilityNodeInfo instances.
- Per-feature reflection wrappers when the generalized bridge can express the operation.
- A separate Kotlin security path or heap.

9. KNOWN ANDROID / PLATFORM LIMITS

- Cut HTML Internet is WebView-scoped, not a device firewall. It deliberately does not block approved reflected java.net, sockets, platform network services, native code, or another process.
- WebSocket traffic cannot be reliably intercepted by the available WebViewClient/ServiceWorkerClient hooks; it is reported as platform-limited, not blocked.
- JavaScriptInterface physical removal/addition may require reload before JavaScript property visibility changes, although every native entry point applies the Bridge gate immediately.
- Android permissions, manifest declarations, hidden-API enforcement, scoped storage, SELinux, secure/protected content, accessibility enablement, notification-listener enablement, root/ADB boundaries, and foreground/background limits remain authoritative.
- MediaProjection consent is one-shot and must not be reused. Projection behavior and secure-content capture require device validation.
- Accessibility screenshots depend on platform support and service enablement; MediaProjection is required where appropriate.
- Exact alarms may require special access and policy justification; the portal reports capability and uses an inexact fallback when exact scheduling is unavailable.
- MANAGE_EXTERNAL_STORAGE, exact alarms, battery-optimization exemption, accessibility, notification listener, overlay access, and special-use foreground services have separate user-consent and Play-distribution policy consequences.
- Generic SYSTEM_ALERT_WINDOW use remains available only through Android's permission model/general reflection; the built-in overlay is an accessibility overlay owned by GlobalService.
- minSdk 30 intentionally leaves older devices secondary. Guards are present for newer APIs, but older-runtime validation was not performed.
- Process death ends in-memory JavaScript state, handles, callbacks, proxies, queues, and temporary grants. Persisted editor/settings recover; JS heap continuity is not promised.
- A malicious or stuck renderer may still consume resources until Android kills it; the native shell and volume recovery are designed to remain independent but require device verification.
- API 36 runtime performance, startup, Activity leak behavior, background survival, and all end-to-end automation remain unresolved because the only available emulator could not maintain system_server under TCG.
